## Implemented slices

**EP02.1:** `modules/miniros-peer` contains real Kotlin and Swift bridges with advertise/discover, explicit connection request, held verification callbacks, confirm/reject, bounded byte send/receive, disconnect and background cleanup. Each endpoint is cleared on stop. Kotlin executes bridge methods on the main queue and ignores callbacks from an older search generation; the cached client supports cleanup after React teardown. Swift checks current manager/advertiser/discoverer identity, bounds discovered contexts, and rejects stale completion/verification callbacks. Neither OS transfer-success callback emits an application receipt. The Swift medium list excludes WebRTC; there is no application cloud/WebSocket path.

**EP02.2 portable implementation:** `protocol.ts`, `store.ts`, `session.ts` provide a strict numbered-fixture protocol. `native-runtime.ts` connects it to real Expo SQLite using exclusive transactions with WAL/FULL durability settings. Receiver insert and a frozen receipt commit in the same transaction, before any receipt send. Lost receipt + resend returns that exact original receipt; duplicate IDs with altered canonical data and duplicate sequences with another ID are conflicts. Optional visual cues occur once per newly committed inbox row; a cue failure cannot undo storage or duplicate a cue on resend. No production sales, financial projections or enrollment grants exist in this spike.

**EP02.3:** the portable fault network has explicit drop/duplicate/reorder/delay controls and bounded queues. The session serializes receive work, catches rejected packets/storage failures without abandoning subsequent work, persists pending sends, and supports cancellation/background pause/reconnection with new manual code confirmation. A local save resolves after its SQLite commit, independent of a stalled native send. A save during a pending send requests another drain. Connected retries run at one-second intervals while work remains, drain bounded batches beyond 256 pending records, and are canceled on stop. No received count is inferred from link state or send success.

**EP02.4 portable preparation:** the native test screen can save one test or 100 numbered tests in either role, show saved/pending/durably received totals after reopen, and display process-local monotonic receipt sample size/p95/max when the runtime offers a monotonic clock. Reconnect excludes abandoned old attempt timings. Timings are diagnostics until collected on named physical phones with documented radio conditions; no latency acceptance data exists in this report.

## Authentication, protocol and storage limits

The short-code comparison is mandatory on both phones. A SHA-256 context binds the expected business, shift, frozen snapshot/hash, authority epoch, test pairing group, device IDs and role before prompting. The SDK comparison token comes from the native negotiated connection; it is not fabricated, used as a custom encryption key, or accepted automatically. A mismatched/foreign context is rejected. Data ingress also checks every scope field, recipient, sender and permitted direction. Public store accept/ack methods recheck incoming scope so a bypass of the parser cannot clear another scope's pending rows.

Synthetic test identities are deliberately visible. Context hashing is a binding checksum, not production grant issuance. Physical in-person SDK code comparison authenticates the selected peer for the test; server-signed staff enrollment/offline grants and their revocation remain later work. An attacker with the same public fixture cannot bypass code comparison, but this spike is not proof of production staff authorization. Reconnect always needs a new comparison; no nearby auto-trust.

| Boundary        | Implemented limit/behavior                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Data shape      | Flat schema; only `test.order` cashier → prep or `test.prep-command` prep → cashier; numbered synthetic text, no financial/payment fields                                                     |
| Wire size       | 16,384 UTF-8 bytes maximum at parser and native boundary; text ≤2,048 UTF-16 units; no arbitrary files/streams                                                                                |
| Integrity       | SHA-256 of canonical flat data via Expo Crypto/native primitive; authenticated native session protects delivery; checksum alone is not authorization                                          |
| Identity/replay | Stable message ID, per-sender fixture sequence; same ID+same canonical data returns frozen receipt; changed payload or sequence collision rejected                                            |
| Scope           | Business/shift/snapshot/hash/epoch/pairing group/sender/recipient checked; directions follow test role                                                                                        |
| Reordering      | Durable inbox accepts only within 256 of its contiguous fixture sequence; gaps remain visible through diagnostic contiguous count                                                             |
| Capacity        | 10,000 stored inbox and outbox rows per local scope; no destructive journal eviction; 64 pending receive tasks; eight discovered candidates; one in-flight comparison; simulator queue ≤1,024 |
| Quarantine      | Latest 64 bounded rejected fixture evidence rows per scope; never accepts production payment payloads                                                                                         |
| Cleanup         | Stop/background removes discovery subscriptions, invalidates connection and timers, retains SQLite rows; resume offers explicit reconnect                                                     |
| Retry           | At-least-once attempts, separately committed durable ACKs; no exactly-once network claim                                                                                                      |

The EP02 fixture sequence/contiguous count is **not** an authoritative financial-journal high-water mark. EP03/04 contracts and storage must be composed through an adapter in a later integrated slice; the spike never upgrades legacy schemaVersion 1 or opens/deletes legacy Dexie data. The isolated database is `miniros-ep02-spike.db`; do not reset it between a resend/restart test.
