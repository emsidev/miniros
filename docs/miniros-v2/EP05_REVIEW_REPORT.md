## P1 finding and verified correction

**P1: native reservation could coexist with a legacy reservation under REPEATABLE READ.** Before the correction, native registration locked the shift and inserted its authority without changing the shift row. A legacy `prepareOfflineShift` transaction that had started while this lock was held retained an older REPEATABLE READ snapshot. After waiting, it saw no native authority and inserted a legacy session. The independent regression demonstrated that both requests fulfilled on different PostgreSQL backend PIDs.

The implementation owner now updates the locked shift's `updatedAt` in the same transaction as creating a new native authority (`administration.ts`). This creates a row version change without changing logical shift state or weakening legacy snapshot isolation. A legacy transaction already using the older snapshot fails with PostgreSQL **40001** and cannot insert a session; retry sees the native reservation.

Both final race tests inspect `pg_stat_activity` and wait for the second backend's actual `wait_event_type='Lock'` before releasing the first transaction. They assert different backend PIDs. Native-first yields one native authority, no legacy session, a 40001 loser and a denied retry. Legacy-first yields one legacy session, no native authority and `LEGACY_RESERVED`. Sequential claim tests pass in both directions. The failing test was retained as a regression, not weakened to accept two owners.

## Actual test boundary

Tests connect only to `127.0.0.1:55432/miniros_ep00_disposable`, a task-owned PostgreSQL 18.0 instance. The strict disposable-target assertion runs before database construction. Unique synthetic businesses, users and shifts avoid collisions with other workers. The suite does not use PGlite or an in-memory database as concurrency evidence.

Supabase `createClient().auth.getUser()` is the **only mocked native authentication boundary**. Tests obtain the actual private-branded `NativeIdentity` through `authenticateNative`; they do not cast an arbitrary identity into authority. A negative test proves an unbranded object fails. All signature generation/verification, schemas, hashes, reducers, SQL, transactions, constraints and service methods execute normally. Ed25519 keypairs are generated by Node crypto and signatures cover the canonical digest text. Deterministic injected server times exercise grant expiry; this does not prove hosted token behavior.

The final Auth factory is isolated in `apps/web/src/lib/supabase/native.ts`, matching the repository's explicit data-access boundary. Source review confirms public environment credentials only, disabled session persistence/automatic refresh/URL detection, no cookie access and a return value limited to `{ auth }`. The native service retains explicit Bearer `getUser` verification and the private identity brand. The relational Supabase client is not exposed to services.

Legacy HTTP identity and cookie adapters are mocked to provide a controlled authorized legacy caller while executing real `prepareOfflineShift` and `synchronizeOfflineAction` services against PostgreSQL. The legacy/native race does not replace either reservation implementation with a fake.
